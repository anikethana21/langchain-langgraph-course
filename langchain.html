Prologue

The Paradigm Shift to Agentic AI

From deterministic rule-based systems to autonomous cognitive agents that perceive, plan, act, and reflect in real time.

The Four Eras of Software Engineering

+-------------------------------------------------------------------------------+ | ERA 1: Deterministic Programming | | Input -> [Explicit If/Else Rules & Functions] -> Output | | (Rule-based, brittle, zero generalization) | +-------------------------------------------------------------------------------+ | v +-------------------------------------------------------------------------------+ | ERA 2: Classical Machine Learning | | Data + Labels -> [Trained Weights & Patterns] -> Predictions | | (Statistical, classification/regression, requires manual feature engineering) | +-------------------------------------------------------------------------------+ | v +-------------------------------------------------------------------------------+ | ERA 3: Generative AI (LLMs & Chatbots) | | Prompt -> [Large Pre-trained Transformer] -> Generated Text | | (Semantic understanding, probabilistic text generation, static knowledge) | +-------------------------------------------------------------------------------+ | v +-------------------------------------------------------------------------------+ | ERA 4: Agentic AI (Autonomous Cognitive Systems) | | Goal -> [Perception -> Planning -> Tool Execution -> Reflection] -> Result | | (Dynamic decision-making, environment interaction, multi-step execution) | +-------------------------------------------------------------------------------+

What is an "Agent"?

A standard LLM is a passive brain in a vat. When given an input prompt, it calculates the next most probable tokens and halts. It cannot inspect the outside world, run code, query your live database, verify its own facts, or correct itself when it makes a mistake.

1

Perception

Receiving inputs, multimodal sensory context, environment feedback, and retrieved knowledge.

2

Cognition (Planning & Reasoning)

Breaking complex goals into sequential sub-tasks, estimating uncertainty, and formulating plans.

3

Action Space (Tools)

Web search APIs, code interpreters, SQL databases, shell execution, and external integrations.

4

Memory (State)

Short-term conversational context buffers, scratchpads, and long-term vector/serialized stores.

5

Self-Correction (Reflection)

Evaluating intermediate tool outputs against the original objective and re-planning dynamically.

Module 1.1

The Anatomy of Large Language Models (LLMs)

Modern LLMs (GPT-4o, Claude 3.5, Gemini 1.5/2.0, Llama 3) are based on the Transformer Architecture (Vaswani et al., 2017).

🧩
Tokenization
Sub-word Encoding

Text is converted into numerical identifiers (tokens). On average, 1 token ≈ 0.75 words (or 4 characters of standard English text). Punctuation, capitalization, and whitespace occupy distinct token boundaries.

🖊
Autoregression
Next-Token Prediction

Models predict one token at a time sequentially. Each newly sampled token is appended to the input context before computing the probability distribution for the subsequent token.

💻
Context Window
Working Memory

The maximum sequence length (N tokens) the model can hold in working attention simultaneously. Exceeding this boundary causes truncation, degradation, or out-of-memory errors.

Mathematical Formula: Autoregressive Next-Token Prediction
P( wₜ₊₁ | w₁, w₂, ..., wₜ )
"Given the history of tokens 1 to t, calculate the conditional probability of every candidate token in vocabulary V being chosen as token t+1."
Module 1.2

Hyperparameter Mechanics: Temperature, Top-P, Top-K

Mathematical formulas, step-by-step numerical examples, and tuning rules for deterministic agent control.

When an LLM produces output, it first computes unnormalized logit scores zi for each token i in vocabulary V. These logits are scaled by temperature T and converted into normalized sampling probabilities using the Softmax Function:

FORMULA 1: Softmax with Temperature Scaling
exp( zᵢ / T ) P(wᵢ) = ──────────────────── ∑ exp( zⱼ / T ) j ∈ V
Where: wᵢ = Candidate token i in vocabulary V | zᵢ = Raw unnormalized logit score predicted for token i | T = Temperature parameter (T > 0) | P(wᵢ) = Probability of selecting token wᵢ (sums to 1.0).

Step-by-Step Numerical Example

Suppose vocabulary V has 3 candidate words with raw logits: z = [ "AI": 4.0, "Cloud": 2.0, "Database": 1.0 ].

Case 1
T = 1.0 (Standard)

exp(4.0 / 1.0) = exp(4.0) ≈ 54.60
exp(2.0 / 1.0) = exp(2.0) ≈ 7.39
exp(1.0 / 1.0) = exp(1.0) ≈ 2.72
Sum = 54.60 + 7.39 + 2.72 = 64.71

P("AI") = 54.60 / 64.71 = 84.4%
P("Cloud") = 7.39 / 64.71 = 11.4%
P("Database") = 2.72 / 64.71 = 4.2%

Case 2 (Recommended for Agents)
T = 0.2 (Deterministic)

Logits ÷ 0.2 magnified 5×: [20, 10, 5]
exp(20) ≈ 4.85 × 10⁸
exp(10) ≈ 2.20 × 10⁴
exp(5) ≈ 148.4

P("AI") = 99.995%
P("Cloud") ≈ 0.0045%
Collapses into near-greedy determinism, eliminating hallucinations.

Case 3
T = 2.0 (High Entropy)

Logits ÷ 2.0 flatten: [2.0, 1.0, 0.5]
exp(2.0) ≈ 7.39 | exp(1.0) ≈ 2.72
exp(0.5) ≈ 1.65
Sum ≈ 11.76

P("AI") = 62.8%
P("Cloud") = 23.1%
P("Database") = 14.1%
High entropy, chaotic exploration.

Hyperparameter Decision Matrix

Parameter Mathematical Mechanism Practical Effect Recommended Setting
Temperature (T) Divides logits prior to exponentiation. When T → 0, distribution collapses to greedy argmax. When T > 1, distribution flattens. Lower = factual, structured output.
Higher = creative writing, brainstorming.		 Agents / RAG / JSON: T ∈ [0.0, 0.2]
Creative / Chat: T ∈ [0.7, 0.9]
Top-P (Nucleus Sampling) Truncates vocabulary to smallest cumulative probability set S such that ∑ P(wᵢ) ≥ P. Prevents sampling extremely unlikely "tail" tokens while keeping diversity. Set to 0.9 or 0.95. Keep either T or Top-P default when tuning the other.
Top-K Caps sampling pool strictly to top K most probable tokens. Hard barrier against low-probability hallucinations. Often 40 to 50 in open-source models.
Module 1.3

Prompt Engineering: Anatomy of an Agent Prompt

A naive prompt produces unpredictable outputs. A production agent prompt must contain five explicit structural blocks.

1

PERSONA & ROLE

Defines identity, domain authority, and perspective. Constrains the vocabulary space to relevant professional domains.

2

OBJECTIVE & TASK

Unambiguous, single-minded mission statement specifying what problem must be resolved.

3

AVAILABLE TOOLS & CONSTRAINTS

Explicit tool whitelist, grounding directives, negative constraints ("NEVER fabricate"), and missing data protocols.

4

REASONING PROCESS (Chain of Thought)

Step-by-step cognitive instructions enforcing verification before action.

5

OUTPUT FORMAT SCHEMA

Machine-parseable contract (JSON, Pydantic, XML) allowing downstream code execution.

Markdown — Production Agent Prompt Template
# 1. PERSONA & ROLE You are an expert Research Analyst Agent specializing in financial markets. # 2. OBJECTIVE & TASK Your task is to analyze quarterly revenue reports and identify growth bottlenecks. # 3. AVAILABLE TOOLS & CONSTRAINTS - You have access to: [web_search, calculator, query_financial_db]. - ONLY use facts found in the retrieved documents. Do NOT fabricate numbers. - If a data point is missing, explicitly state "DATA_UNAVAILABLE". # 4. REASONING PROCESS (Chain of Thought) Before returning your final output, think step-by-step: 1. Parse the query to identify ticker symbol and relevant fiscal quarters. 2. Formulate tool queries and inspect the raw metrics. 3. Compute Year-over-Year (YoY) percentage delta using the calculator. # 5. OUTPUT FORMAT SCHEMA Return your final answer strictly as valid JSON adhering to: { "ticker": string, "yoy_growth_percentage": float, "key_drivers": [string], "risks": [string] }
Module 1.4

LangChain & LCEL (LangChain Expression Language)

Declarative composition of LLM components using Unix-style pipe operators (|) and the standard Runnable protocol.

The LCEL Composition Formula
Chain = PromptTemplate | ChatModel | OutputParser
Data flows from left to right. Every component implements the Runnable interface: invoke(), stream(), batch(), ainvoke().
Python — Complete LCEL Pipeline Implementation
from langchain_core.prompts import ChatPromptTemplate from langchain_core.output_parsers import StrOutputParser from langchain_openai import ChatOpenAI # 1. Define Prompt Template prompt = ChatPromptTemplate.from_messages([ ("system", "You are an AI assistant that answers questions in concise bullet points."), ("human", "{user_question}") ]) # 2. Define Model model = ChatOpenAI(model="gpt-4o", temperature=0) # 3. Define Parser parser = StrOutputParser() # 4. Compose via LCEL Pipe Operator chain = prompt | model | parser # 5. Execution (Runnable Protocol) response = chain.invoke({"user_question": "Explain RAG in 3 sentences."}) print(response)
Module 2.1

The RAG Imperative: Solving the Triple Limitations of LLMs

Grounding large language models with external vector search to eliminate hallucinations, bridge knowledge cutoffs, and access private enterprise data.

1. Hallucinations

LLMs optimize next-token statistical likelihood, not empirical truth. Under uncertainty, they construct confident fabrications.

2. Knowledge Cutoff

Training sets are frozen snapshots in time. Models are entirely blind to events, updates, or releases following the cutoff.

3. Private Data Blindness

Models have never seen your internal company PDFs, SQL databases, customer tickets, or proprietary repos.

[User Query] ------------------------+ | | v v [Embedding Model] [Prompt Template] | ^ v | [Vector Similarity Search] | | | v | [Top-K Document Chunks] -------------+ | v [LLM Model] | v [Grounded Answer]

Module 2.3 — Pillar 2

Chunking & Splitting Mathematics

Why chunk overlap is mandatory, how RecursiveCharacterTextSplitter operates, and boundary preservation.

LLMs cannot ingest 500-page books in a single prompt effectively, nor can vector search match a query against a 50-page document without noise. We must slice documents into chunks.

Document Text: [ Paragraph 1 (400 tokens) ] [ Paragraph 2 (400 tokens) ] [ Paragraph 3 (400 tokens) ] | v Recursive Splitter (chunk_size=500, chunk_overlap=100) --------------------------------------------------------------------------------- Chunk 1: [ Paragraph 1 + Start of Paragraph 2 ] Chunk 2: [ Overlap tail of Para 1 + Full Para 2 + Start of Para 3 ]

Why Chunk Overlap is Mandatory

If a crucial fact spans across the boundary of Chunk 1 and Chunk 2:
- Chunk 1 ends with: "...The total net profit was"
- Chunk 2 begins with: "$42.5 million in Q3..."

Without overlap, neither chunk contains the complete semantic idea. Overlap preserves boundary context and ensures semantic integrity during embedding lookup.

Python — Recursive Character Text Splitter
from langchain_text_splitters import RecursiveCharacterTextSplitter splitter = RecursiveCharacterTextSplitter( chunk_size=1000, # Max characters per chunk chunk_overlap=200, # Sliding window character overlap length_function=len, separators=["\n\n", "\n", ". ", " ", ""] ) chunks = splitter.split_documents(pdf_documents) print(f"Original Pages: {len(pdf_documents)} -> Processed Chunks: {len(chunks)}")
Module 2.4 — Pillar 3

Vector Embeddings & High-Dimensional Geometry

Mapping human language into continuous vector spaces. Complete cosine similarity formula, proof, and 2D numerical example.

FORMULA 2: Vector Cosine Similarity
A · B CosineSim(A, B) = ───────────────── ||A|| × ||B|| n ∑ ( Aᵢ × Bᵢ ) i=1 = ───────────────────────────────── _________________ _________________ / n / n / ∑ ( Aᵢ )² / ∑ ( Bᵢ )² i=1 i=1
Where: A, B = Embedding vectors of Query and Chunk | A · B = Dot product | ||A|| = Euclidean L2 norm (vector magnitude) | n = Dimensionality (e.g., 1536 for OpenAI embeddings).
cos(θ) = +1.0 (θ = 0°)

Identical semantic meaning (e.g., "car" and "automobile"). Vectors point in exactly the same direction.

cos(θ) = 0.0 (θ = 90°)

Completely unrelated / orthogonal (e.g., "quantum mechanics" and "banana recipe"). Zero correlation.

cos(θ) = -1.0 (θ = 180°)

Diametrically opposite semantic concepts. Vectors point in directly opposite directions.

2D Numerical Example

Suppose query vector A = [0.8, 0.6] and document chunk vector B = [0.6, 0.8]:
1. Dot Product (A · B): (0.8 × 0.6) + (0.6 × 0.8) = 0.48 + 0.48 = 0.96
2. Magnitudes (||A|| and ||B||):
    ||A|| = √(0.8² + 0.6²) = √(0.64 + 0.36) = √1.0 = 1.0
    ||B|| = √(0.6² + 0.8²) = √(0.36 + 0.64) = √1.0 = 1.0
3. Similarity Calculation:
    CosineSim(A, B) = 0.96 / (1.0 × 1.0) = 0.96 → 96% match (extremely strong semantic affinity!)

Module 2.7

Production Challenges & Advanced Retrieval (MMR)

Overcoming the redundancy of naive Top-K through Maximal Marginal Relevance (MMR) and diversity balancing.

FORMULA 3: Maximal Marginal Relevance (MMR)
MMR = argmax [ λ · Sim₁(dᵢ, q) - (1 - λ) · max Sim₂(dᵢ, dⱼ) ] dᵢ∈DS dⱼ∈S
Where: q = The user query vector | D = Full pool of candidate retrieved document chunks | S = Set of chunks ALREADY selected into context | D S = Remaining candidate chunks | Sim₁(·) = Query relevance | Sim₂(·) = Similarity between candidate chunk and already selected chunks | λ = Trade-off parameter [0.0, 1.0].
λ = 1.0 ────────────────────── λ = 0.7 ────────────────────── λ = 0.0 [Pure Relevance] [The RAG Sweet Spot] [Pure Diversity] Identical to naive Top-K. High relevance to query, Maximum variety. Risks redundant chunks. penalizes duplicate content. May pull off-topic chunks.
Module 3.1

Giving LLMs Hands: The Function Calling Paradigm

Transforming text generators into system actuators. How LLMs inspect tool schemas, return structured invocation intents, and consume observations.

1

Tool Schema Registration

The developer passes a list of available tools (with names, descriptions, and JSON parameter schemas) to the LLM during model invocation.

2

Structured Tool Call Request

The LLM analyzes the query, determines external action is required, and emits structured JSON: {"name": "fetch_stock_price", "arguments": {"symbol": "AAPL"}}.

3

Local Runtime Execution

Your local Python runtime catches the request, executes the actual code against live systems/APIs, and collects the result: "$224.50".

4

Observation Feedback

The output is wrapped in a ToolMessage matching the tool's tool_call_id and appended to the message history.

5

Synthesis & Response

The LLM receives the tool output, contextualizes it against the original prompt, and generates the final response.

Module 3.4

Anatomy of the Agent Execution Loop

Implementing the ReAct cognitive cycle from scratch as a finite state machine with model tool binding.

Python — Complete Agent Loop Implementation
from langchain_openai import ChatOpenAI from langchain_core.messages import HumanMessage, SystemMessage, ToolMessage # 1. Bind tools to model llm = ChatOpenAI(model="gpt-4o", temperature=0) llm_with_tools = llm.bind_tools(tools) tool_map = {t.name: t for t in tools} # 2. Execution Loop Finite State Machine def run_agent_loop(query: str, max_iterations: int = 5): messages = [ SystemMessage(content="You are an autonomous analytical assistant. Use tools when needed."), HumanMessage(content=query) ] for step in range(max_iterations): # Model makes a decision ai_msg = llm_with_tools.invoke(messages) messages.append(ai_msg) # If no tool calls requested, the agent is done! if not ai_msg.tool_calls: return ai_msg.content # Execute each requested tool call for tool_call in ai_msg.tool_calls: tool_name = tool_call["name"] tool_args = tool_call["args"] tool_id = tool_call["id"] selected_tool = tool_map[tool_name] observation = selected_tool.invoke(tool_args) # Feed tool observation back to message history messages.append(ToolMessage(content=str(observation), tool_call_id=tool_id)) return "Error: Agent reached maximum iteration limit without resolving."
Module 4.1 & 4.2

Multi-Agent Systems: Limits of Monolithic Agents & Topologies

Why single agents fail at scale and the 3 foundational multi-agent organizational patterns.

Cognitive Overload

A single prompt cannot enforce diverse personas (rigorous math vs creative writing vs legal compliance) without performance collapse.

Context Poisoning

Accumulating multiple web scrapes, SQL outputs, and tool observations bloats working memory and degrades reasoning.

Self-Grading Bias

Foundation models struggle to evaluate their own hallucinations impartially. Dedicated critic agents are mandatory.

Multi-Agent Topologies

1. Sequential Pipeline [Agent A: Planner] -> [Agent B: Researcher] -> [Agent C: Writer] 2. Hierarchical Supervisor (Star Topology) [Supervisor Agent] / | [Web Agent] [DB Agent] [Code Agent] 3. Generator-Critic Loop (Reflection Pattern) +---------> [Writer Agent] ---------> [Draft] | ^ | | | v [Feedback] [Revision Node] <--- [Critic / Evaluator] | (Passes Threshold?) | v [Final Output]

1. cache_manager.py (The .pkl Persistence Layer)

Python — cache_manager.py
import os import pickle from typing import Any, Optional CACHE_DIR = os.path.join(os.path.dirname(__file__), "cache") os.makedirs(CACHE_DIR, exist_ok=True) def get_cache_path(filename: str) -> str: if not filename.endswith(".pkl"): filename += ".pkl" return os.path.join(CACHE_DIR, filename) def save_to_pkl(data: Any, filename: str) -> str: path = get_cache_path(filename) with open(path, "wb") as f: pickle.dump(data, f, protocol=pickle.HIGHEST_PROTOCOL) print(f"[CACHE] Saved {type(data).__name__} to: {path}") return path def load_from_pkl(filename: str) -> Optional[Any]: path = get_cache_path(filename) if not os.path.exists(path): return None try: with open(path, "rb") as f: return pickle.load(f) except Exception as e: print(f"[CACHE ERROR] Failed to load {path}: {e}") return None def exists_in_cache(filename: str) -> bool: path = get_cache_path(filename) return os.path.exists(path) and os.path.getsize(path) > 0

2. tools.py (Web Tools with Automatic .pkl Caching)

Python — tools.py
import os import requests from bs4 import BeautifulSoup from dotenv import load_dotenv from langchain_core.tools import tool from tavily import TavilyClient from cache_manager import load_from_pkl, save_to_pkl load_dotenv() tavily_key = os.getenv("TAVILY_API_KEY", "") tavily = TavilyClient(api_key=tavily_key) if tavily_key else None @tool def tavily_search(query: str) -> str: """Search the web using Tavily API. Results are cached into search_cache.pkl.""" cache_data = load_from_pkl("search_cache.pkl") or {} clean_query = query.strip().lower() if clean_query in cache_data: return cache_data[clean_query] if not tavily: fallback = f"[MOCK SEARCH for '{query}']: Relevant facts regarding {query}." cache_data[clean_query] = fallback save_to_pkl(cache_data, "search_cache.pkl") return fallback response = tavily.search(query=query, max_results=5) results = response.get("results", []) output = [f"Title: {r.get('title')}\nURL: {r.get('url')}\nContent: {r.get('content')}" for r in results] formatted = "\n---\n".join(output) if output else "No results found." cache_data[clean_query] = formatted save_to_pkl(cache_data, "search_cache.pkl") return formatted @tool def scrape_webpage(url: str) -> str: """Scrapes raw web page text content, stripping HTML tags, and caches into scrape_cache.pkl.""" cache = load_from_pkl("scrape_cache.pkl") or {} if url in cache: return cache[url] resp = requests.get(url, headers={"User-Agent": "Mozilla/5.0"}, timeout=10) soup = BeautifulSoup(resp.text, "html.parser") for el in soup(["script", "style", "nav", "footer", "header"]): el.decompose() paragraphs = [p.get_text(strip=True) for p in soup.find_all("p") if len(p.get_text(strip=True)) > 40] content = "\n\n".join(paragraphs[:15]) cache[url] = content save_to_pkl(cache, "scrape_cache.pkl") return content

import os import pickle import time from typing import Any, Optional CACHE_DIR = os.path.join(os.path.dirname(__file__), "pkl_cache") os.makedirs(CACHE_DIR, exist_ok=True) def get_cache_file_path(name: str) -> str: if not name.endswith(".pkl"): name += ".pkl" return os.path.join(CACHE_DIR, name) def save_pickle(obj: Any, name: str) -> str: path = get_cache_file_path(name) start = time.time() with open(path, "wb") as f: pickle.dump(obj, f, protocol=pickle.HIGHEST_PROTOCOL) duration = round((time.time() - start) * 1000, 2) size_kb = round(os.path.getsize(path) / 1024, 2) print(f"[PKL EXPORT] Serialized '{name}' ({size_kb} KB) in {duration}ms -> {path}") return path def load_pickle(name: str) -> Optional[Any]: path = get_cache_file_path(name) if not os.path.exists(path): return None try: start = time.time() with open(path, "rb") as f: obj = pickle.load(f) duration = round((time.time() - start) * 1000, 2) print(f"[PKL IMPORT] Deserialized '{name}' in {duration}ms") return obj except Exception as e: print(f"[PKL ERROR] Corrupted pickle file '{name}': {e}") return None def is_cached(name: str) -> bool: path = get_cache_file_path(name) return os.path.exists(path) and os.path.getsize(path) > 0

import numpy as np from typing import List, Dict, Any, Tuple from cache_manager import save_pickle, load_pickle, is_cached from ingest import ingest_video_transcript class VideoVectorIndex: def __init__(self, video_id: str): self.video_id = video_id self.chunks: List[Dict[str, Any]] = [] self.embeddings: np.ndarray = None def build(self, chunks: List[Dict[str, Any]]) -> "VideoVectorIndex": self.chunks = chunks vecs = [self._embed(c["text"]) for c in chunks] self.embeddings = np.array(vecs) return self def _embed(self, text: str) -> np.ndarray: np.random.seed(abs(hash(text)) % (2**32)) vec = np.random.randn(128) return vec / np.linalg.norm(vec) def search(self, query: str, top_k: int = 3) -> List[Tuple[Dict[str, Any], float]]: q_vec = self._embed(query) similarities = np.dot(self.embeddings, q_vec) top_indices = np.argsort(similarities)[::-1][:top_k] return [(self.chunks[idx], float(similarities[idx])) for idx in top_indices] def get_or_build_video_index(video_id: str, force_rebuild: bool = False) -> VideoVectorIndex: pkl_name = f"vector_index_{video_id}.pkl" if not force_rebuild and is_cached(pkl_name): return load_pickle(pkl_name) chunks = ingest_video_transcript(video_id) index = VideoVectorIndex(video_id).build(chunks) save_pickle(index, pkl_name) # Convert and serialize compiled index to .pkl return index
