Core Concepts

Generative AI vs. Agentic AI: The Fundamental Shift

Traditional Generative AI is a one-way street: you give a prompt, the model calculates logits, and it returns text. If it hallucinates or misses a step, you have no recourse. LangGraph transforms this into a stateful, cyclical graph where agents plan, execute, inspect their own work, branch concurrently, and loop until success.

🎯 Pedagogical Analogy: The Rapid Typist vs The Operations Director
A standalone LLM is like a world-class typist sitting in an isolated soundproof room: whatever prompt slides under the door, they type out a brilliant 500-word response in 3 seconds and slide it back. They cannot check if the server is down, cannot consult a colleague, and cannot correct a mistake.

LangGraph is appointing an Operations Director with a whiteboard (State). The Director dispatches tasks to specialists (Nodes), merges their findings (Reducers), routes based on conditions (Conditional Edges), and walks into the CEO's office for approval before wiring money (Interrupt).
⚖️ Architectural Showdown: Chains vs Autonomous Agents vs LangGraph StateGraphs
Feature Linear Chains (LCEL) Legacy AgentExecutor LangGraph StateGraph
Flow Control Strictly Directed Acyclic (DAG) Black-box while loop Arbitrary Cyclic & Parallel Graph
State Persistence Volatile (Lost after invoke) Internal memory buffer First-class durable checkpointers (SQLite/Postgres)
Branching & Concurrency Manual async gathers Sequential only Native Fan-Out & Reducer Fan-In
Human Intervention None (Must terminate chain) Extremely brittle callbacks Native interrupt() and Command(resume=...)
Production Readiness High (For simple ETL) Deprecated by LangChain The Modern Industry Standard
State Architecture

State Modeling: TypedDict vs. Pydantic

In LangGraph, every graph is parameterized by a central State Schema. Nodes do not receive arbitrary parameters; they receive the current state dictionary and return updates (deltas) that are merged back into the state.

🎯 Pedagogical Analogy: The Operating Room Whiteboard
Think of the LangGraph State as a large magnetic whiteboard hanging in a surgical operating room. The Surgeon, the Anesthesiologist, and the Head Nurse all look at the exact same board. When the Anesthesiologist administers a drug, they write the dosage on the board. The Surgeon reads the board before making an incision. Nobody whispers in secret corridors—all communication happens through the central, synchronized board.
⚖️ State Modeling Trade-Offs: TypedDict vs Pydantic BaseModel
Dimension TypedDict (Standard) Pydantic BaseModel When to Choose Which?
Runtime Validation None (Type hints only at edit/compile time) Strict (Validates types, lengths, regex on instantiation) Use Pydantic when accepting raw, untrusted user/API payloads
Performance Overhead Zero (Native Python dictionary) Slight overhead (Instantiates validation objects) Use TypedDict for high-throughput, latency-critical pipelines
LangGraph Ecosystem Native default across documentation Supported via StateGraph(MyModel) TypedDict is 90% of production LangGraph architectures
💡 Developer Empathy: The "In-Place Mutation" Trap
A catastrophic bug that causes silent graph bugs is writing state["messages"].append(msg) inside a node.

Why it fails: LangGraph relies on immutability and state snapshots for checkpointing and time-travel replay. Modifying state in-place corrupts history!

Golden Rule: Nodes must ALWAYS treat input state as read-only, and return a dictionary of state updates (e.g. return {"messages": [msg]}).
states.py — TypedDict & Pydantic Implementations
import os
from typing import TypedDict
from pydantic import BaseModel, Field

# =====================================================================
# 1) TypedDict Approach (Most Common in LangGraph)
# Lightweight, native Python dictionary with compile-time type hints.
# Best for high-throughput, low-overhead pipelines.
# =====================================================================
class SimpleState(TypedDict):
    query: str
    intermediate_steps: list[str]
    final_output: str

# =====================================================================
# 2) Pydantic Approach (Runtime Validation & Coercion)
# Strict runtime type checking, default values, and schema enforcement.
# Best when accepting arbitrary untrusted user or webhook inputs.
# =====================================================================
class ValidatedState(BaseModel):
    query: str = Field(..., min_length=3, description="User input question")
    intermediate_steps: list[str] = Field(default_factory=list, description="Audit trace")
    final_output: str = Field(default="", description="Synthesized response")
Project 1

Sequential Pipeline: Copyeditor → Hook Creator → Hinglish Translator

The fundamental unit of graph orchestration is the Sequential Workflow. Each node performs a specialized transformation and passes the baton to the next node via explicit directed edges.

🎯 Pedagogical Analogy: The Automotive Assembly Line
In an automotive factory, a car chassis moves along a conveyor track. Station 1 installs the engine (Copyeditor expands the topic). Station 2 bolts on the aerodynamic spoiler (Hook Creator drafts the viral intro). Station 3 paints the car with custom regional decals (Hinglish Translator adapts the tone). No station tries to build the whole car from scratch.
🔬 Under the Hood: Graph Compilation and Node Execution
When you call workflow.compile(), LangGraph validates graph topology: checking for orphaned nodes, unreachable endpoints, and schema conformance. When invoked, it starts at START, passes state to the first node, merges the emitted delta, and follows outgoing edges until hitting END.
sequential_base.py — Production Sequential Pipeline
import os
from typing import TypedDict
from langchain_openai import ChatOpenAI
from langchain_core.messages import SystemMessage, HumanMessage
from langgraph.graph import StateGraph, START, END

# Step 1: Define Pipeline State
class ContentState(TypedDict):
    raw_topic: str
    editorial_draft: str
    video_hook: str
    hinglish_script: str

# Central Deterministic LLM
llm = ChatOpenAI(model="gpt-4o", temperature=0.3)

# Step 2: Define Node 1 - Copyeditor
def copyeditor_node(state: ContentState) -> dict:
    prompt = [
        SystemMessage(content="You are a senior tech copyeditor. Expand this topic into an informative 2-paragraph draft."),
        HumanMessage(content=state["raw_topic"])
    ]
    res = llm.invoke(prompt)
    return {"editorial_draft": res.content}

# Step 2: Define Node 2 - Video Scriptwriter Hook
def video_hook_node(state: ContentState) -> dict:
    prompt = [
        SystemMessage(content="You are a viral YouTube creator. Create a 15-second high-retention video hook based on this draft."),
        HumanMessage(content=state["editorial_draft"])
    ]
    res = llm.invoke(prompt)
    return {"video_hook": res.content}

# Step 2: Define Node 3 - Indian Hinglish Translator
def hinglish_translator_node(state: ContentState) -> dict:
    prompt = [
        SystemMessage(content="Translate this video hook into engaging, conversational Indian Hinglish (mix of Hindi & English) for urban youth."),
        HumanMessage(content=state["video_hook"])
    ]
    res = llm.invoke(prompt)
    return {"hinglish_script": res.content}

# Step 3: Build Sequential Graph
workflow = StateGraph(ContentState)

workflow.add_node("copyeditor", copyeditor_node)
workflow.add_node("hook_creator", video_hook_node)
workflow.add_node("hinglish_translator", hinglish_translator_node)

workflow.add_edge(START, "copyeditor")
workflow.add_edge("copyeditor", "hook_creator")
workflow.add_edge("hook_creator", "hinglish_translator")
workflow.add_edge("hinglish_translator", END)

app = workflow.compile()

# Execution Driver
if __name__ == "__main__":
    initial_input = {"raw_topic": "Vector Embeddings and Cosine Similarity in RAG"}
    result = app.invoke(initial_input)
    print("=== FINAL HINGLISH SCRIPT ===")
    print(result["hinglish_script"])
Project 2

Parallel Workflows & Annotated State Reducers

When multiple evaluations or searches can happen concurrently, running them sequentially wastes valuable seconds. LangGraph supports Parallel Fan-Out from START, triggering multiple nodes at the same time. However, when multiple nodes write to the same key, they will collide unless coordinated with an `Annotated` Reducer.

🎯 Pedagogical Analogy: Olympic Judges & The Scorekeeper Clerk
In Olympic figure skating, 3 specialized judges (Toxicity, Copyright, Cultural Sensitivity) evaluate a performance simultaneously. If all three ran up to a single chalkboard and tried to overwrite the same box marked "Score", chaos ensues! The Reducer is the official Scorekeeper Clerk: they collect the three separate scorecards and merge them neatly into a single official ledger.
💡 Developer Empathy: The Overwrite Disaster!
If you create 3 parallel nodes that return {"scores": ...} on an un-annotated state key, Python dictionary semantics dictate that whichever node finishes last completely overwrites the results of the other two! You lose 66% of your audit data silently.

The Fix: Annotate the state field with a reducer function: scores: Annotated[dict, merge_score_dicts].
parallel_reducers.py — Concurrent Fan-Out & Custom Reducer
import os
from typing import TypedDict, Annotated
from langchain_openai import ChatOpenAI
from langchain_core.messages import SystemMessage, HumanMessage
from langgraph.graph import StateGraph, START, END

# Custom Reducer: Merges dictionaries emitted by concurrent parallel branches
def merge_score_dicts(left: dict, right: dict) -> dict:
    merged = left.copy() if left else {}
    if right:
        merged.update(right)
    return merged

# State with Annotated Reducer
class SafetyState(TypedDict):
    user_content: str
    # Annotated with custom reducer ensures concurrent branch outputs merge without overwriting!
    safety_audit_scores: Annotated[dict, merge_score_dicts]
    final_verdict: str

llm = ChatOpenAI(model="gpt-4o", temperature=0.0)

# Branch 1: Toxicity Analysis Node
def toxicity_node(state: SafetyState) -> dict:
    prompt = [
        SystemMessage(content="Score toxicity from 0 to 100 as integer only."),
        HumanMessage(content=state["user_content"])
    ]
    res = llm.invoke(prompt)
    return {"safety_audit_scores": {"toxicity": res.content.strip()}}

# Branch 2: Copyright & Plagiarism Check Node
def copyright_node(state: SafetyState) -> dict:
    prompt = [
        SystemMessage(content="Score copyright risk from 0 to 100 as integer only."),
        HumanMessage(content=state["user_content"])
    ]
    res = llm.invoke(prompt)
    return {"safety_audit_scores": {"copyright_risk": res.content.strip()}}

# Branch 3: Regional & Cultural Sensitivity Node
def cultural_node(state: SafetyState) -> dict:
    prompt = [
        SystemMessage(content="Score cultural sensitivity from 0 to 100 as integer only."),
        HumanMessage(content=state["user_content"])
    ]
    res = llm.invoke(prompt)
    return {"safety_audit_scores": {"cultural_score": res.content.strip()}}

# Build Graph with Parallel Fan-Out
builder = StateGraph(SafetyState)

builder.add_node("check_toxicity", toxicity_node)
builder.add_node("check_copyright", copyright_node)
builder.add_node("check_cultural", cultural_node)

# Fan-out: All 3 nodes trigger simultaneously from START
builder.add_edge(START, "check_toxicity")
builder.add_edge(START, "check_copyright")
builder.add_edge(START, "check_cultural")

# Fan-in: All 3 nodes complete into END
builder.add_edge("check_toxicity", END)
builder.add_edge("check_copyright", END)
builder.add_edge("check_cultural", END)

safety_app = builder.compile()

if __name__ == "__main__":
    out = safety_app.invoke({"user_content": "AI is replacing junior developers in 2026."})
    print("=== PARALLEL AUDIT SCORES ===")
    print(out["safety_audit_scores"])
Project 3

Conditional Routing & Multi-PDF RAG Architecture

In enterprise systems, stuffing 50 different PDF documents into a single giant vector store causes severe semantic dilution and irrelevant retrieval. In Project 3, we implement an intelligent Conditional Router that classifies the user's intent and dynamically dispatches to specialized vector indices.

🎯 Pedagogical Analogy: The Hospital Emergency Room Triage Nurse
When a patient walks into a hospital emergency room, they don't get thrown into a random room with all medical instruments. A Triage Nurse (Classifier Node) checks their symptoms: cardiac arrest goes straight to Cardiology (Academic Handbook retriever), a broken bone goes to Orthopedics (Fee Structure retriever), and general flu symptoms go to General Practice (General LLM).
⚖️ Multi-Index RAG vs Monolithic Vector Database
Strategy Retrieval Precision Index Maintenance Access Control Query Latency
One Giant Monolithic Index Poor (Semantic collisions across departments) High risk (One corrupt doc impacts all) Difficult to enforce per-doc permissions Slower as collection scales to millions
Conditional Routed Indices High (Grounded strictly in domain index) Modular (Update fees without touching academics) Granular ACLs per department collection Fast sub-collection targeted searches
conditional_RAG.py — Dynamic Intent Routing Pipeline
import os
from typing import TypedDict, Annotated
from langchain_openai import ChatOpenAI, OpenAIEmbeddings
from langchain_community.vectorstores import Chroma
from langchain_core.messages import SystemMessage, HumanMessage
from langgraph.graph import StateGraph, START, END

# Step 1: Build RAG Retrievers
embeddings = OpenAIEmbeddings(model="text-embedding-3-small")

academics_db = Chroma.from_texts(
    ["The grading criteria requires 85% attendance and passing all 4 module exams."],
    embedding=embeddings, collection_name="academics"
).as_retriever(search_kwargs={"k": 1})

fees_db = Chroma.from_texts(
    ["Tuition is $12,000 per year. Late payment incurs a 5% monthly compounding penalty."],
    embedding=embeddings, collection_name="fees"
).as_retriever(search_kwargs={"k": 1})

# Step 2: Define State
class MultiRAGState(TypedDict):
    user_query: str
    target_category: str
    retrieved_context: str
    final_response: str

llm = ChatOpenAI(model="gpt-4o", temperature=0.0)

# Step 3: Nodes
def query_classifier_node(state: MultiRAGState) -> dict:
    prompt = [
        SystemMessage(content="Classify this student question into exactly one label: 'ACADEMICS', 'FEES', or 'GENERAL'."),
        HumanMessage(content=state["user_query"])
    ]
    label = llm.invoke(prompt).content.strip().upper()
    return {"target_category": label}

def academics_retriever_node(state: MultiRAGState) -> dict:
    docs = academics_db.invoke(state["user_query"])
    return {"retrieved_context": "\n".join([d.page_content for d in docs])}

def fees_retriever_node(state: MultiRAGState) -> dict:
    docs = fees_db.invoke(state["user_query"])
    return {"retrieved_context": "\n".join([d.page_content for d in docs])}

def general_llm_node(state: MultiRAGState) -> dict:
    return {"retrieved_context": "No documents needed. Answer using general world knowledge."}

def answer_synthesis_node(state: MultiRAGState) -> dict:
    prompt = [
        SystemMessage(content=f"Answer the query using this context:\n{state['retrieved_context']}"),
        HumanMessage(content=state["user_query"])
    ]
    res = llm.invoke(prompt)
    return {"final_response": res.content}

# Step 4: Conditional Router Function
def route_query(state: MultiRAGState) -> str:
    category = state.get("target_category", "")
    if "ACADEMICS" in category:
        return "academics_retriever"
    elif "FEES" in category:
        return "fees_retriever"
    else:
        return "general_llm"

# Step 5: Build Graph
builder = StateGraph(MultiRAGState)

builder.add_node("classifier", query_classifier_node)
builder.add_node("academics_retriever", academics_retriever_node)
builder.add_node("fees_retriever", fees_retriever_node)
builder.add_node("general_llm", general_llm_node)
builder.add_node("synthesizer", answer_synthesis_node)

builder.add_edge(START, "classifier")
builder.add_conditional_edges("classifier", route_query, {
    "academics_retriever": "academics_retriever",
    "fees_retriever": "fees_retriever",
    "general_llm": "general_llm"
})
builder.add_edge("academics_retriever", "synthesizer")
builder.add_edge("fees_retriever", "synthesizer")
builder.add_edge("general_llm", "synthesizer")
builder.add_edge("synthesizer", END)

rag_app = builder.compile()

if __name__ == "__main__":
    q = "What happens if I fail to pay tuition on time?"
    print(rag_app.invoke({"user_query": q})["final_response"])
Project 4

Iterative Workflow with Tools & Strict Reviewer Loop

Single-shot LLM outputs frequently fall short of publication standards. Project 4 implements a cyclical feedback loop where a Research Writer generates content and a ruthless Reviewer audits it against 7 Strict Editorial Criteria, looping back until quality thresholds are satisfied.

🎯 Pedagogical Analogy: The Investigative Reporter & The Senior Editor
A rookie journalist (Writer Node) writes a breaking story. They don't immediately publish it to the front page! They slide the draft across the desk to the Pulitzer-winning Senior Editor (Reviewer Node). The Editor marks red ink all over it: "Where are the citations? Cut the fluff. Fix paragraph 2." The journalist revises and resubmits. Only when the editor gives an 85+ score does the printing press start rolling.
🔬 The 7 Strict Editorial Criteria Evaluated by the Reviewer
  1. Direct Technical Accuracy: Zero factual hallucinations or invented APIs.
  2. Complete Absence of Generic Fluff: No filler words ("In conclusion", "As an AI model").
  3. Clear Architectural Breakdown: Explicit node and edge relationships.
  4. Inclusion of Failure Modes: Explaining where systems break in production.
  5. Actionable Implementation Advice: Real, practical engineering steps.
  6. Concise Formatting: Clean bullet points, headers, and code callouts.
  7. Concrete Code or Formulas: Verified syntax and mathematical precision.
💡 Developer Empathy: The Infinite Loop Money Drain!
If your reviewer's criteria are too strict or the model gets stuck in a loop, the graph will execute 1,000 times, consuming hundreds of dollars in API credits within minutes!

Mandatory Safeguard: Always implement a hard attempt counter (e.g. if attempts >= 3: return "publish") in your conditional exit router.
iterative_tools.py — Cyclical Reviewer & Quality Gate
import os
from typing import TypedDict, Annotated
from langchain_openai import ChatOpenAI
from langchain_core.messages import SystemMessage, HumanMessage
from langgraph.graph import StateGraph, START, END

# Tools & Models
llm = ChatOpenAI(model="gpt-4o", temperature=0.2)

# State
class ResearchState(TypedDict):
    topic: str
    current_draft: str
    reviewer_critique: str
    quality_score: int
    attempt_count: int

def writer_node(state: ResearchState) -> dict:
    attempts = state.get("attempt_count", 0) + 1
    feedback = state.get("reviewer_critique", "Initial draft.")
    prompt = [
        SystemMessage(content=f"You are a rigorous research writer. Attempt #{attempts}. Critique: {feedback}"),
        HumanMessage(content=f"Topic: {state['topic']}\nImprove the draft addressing all critiques.")
    ]
    res = llm.invoke(prompt)
    return {"current_draft": res.content, "attempt_count": attempts}

def reviewer_node(state: ResearchState) -> dict:
    prompt = [
        SystemMessage(content="""You are a ruthless Senior Editor.
Evaluate the draft against these 7 Strict Criteria:
1. Direct technical accuracy
2. Complete absence of generic fluff
3. Clear architectural breakdown
4. Inclusion of failure modes
5. Actionable implementation advice
6. Concise formatting
7. Concrete code or formulas

Output format:
SCORE: <0-100>
CRITIQUE: <specific shortcomings>
"""),
        HumanMessage(content=state["current_draft"])
    ]
    res = llm.invoke(prompt).content
    
    # Parse score
    score = 70
    if "SCORE:" in res:
        try:
            score = int(res.split("SCORE:")[1].split()[0].strip())
        except:
            pass
    return {"reviewer_critique": res, "quality_score": score}

# Router Decision
def should_continue_review(state: ResearchState) -> str:
    if state["quality_score"] >= 85 or state["attempt_count"] >= 3:
        return "publish"
    return "revise"

# Build Graph
builder = StateGraph(ResearchState)
builder.add_node("writer", writer_node)
builder.add_node("reviewer", reviewer_node)

builder.add_edge(START, "writer")
builder.add_edge("writer", "reviewer")
builder.add_conditional_edges("reviewer", should_continue_review, {
    "revise": "writer",
    "publish": END
})

iter_app = builder.compile()

if __name__ == "__main__":
    result = iter_app.invoke({"topic": "Explain LangGraph State Reducers", "attempt_count": 0})
    print(f"Passed with Score {result['quality_score']} in {result['attempt_count']} attempts!")
    print(result["current_draft"][:300] + "...")
Project 5

Human-in-the-Loop (HITL) & Checkpoint Interrupts

Autonomous agents must never perform high-stakes, irreversible operations (such as wiring $25,000, deleting customer tables, or sending bulk emails) without explicit human oversight. LangGraph provides native Human-in-the-Loop capabilities via interrupt() backed by durable checkpointers.

🎯 Pedagogical Analogy: The Dual-Key Nuclear Launch Escrow
A missile launch computer can calculate target coordinates, align satellite guidance, and pressurize fuel tanks autonomously. But the final launch sequence physically halts at a dual-key lock box. Two human officers must physically insert keys and turn them simultaneously. In LangGraph, interrupt() pauses execution, saves state to disk, and freezes until a human turns the cryptographic key via Command(resume=...).
⚖️ LangGraph Checkpointers: MemorySaver vs SqliteSaver vs PostgresSaver
Checkpointer Storage Medium Multi-Process Support Durability Production Suitability
MemorySaver Python In-Memory Dict No (Single process) Volatile (Lost on restart) Local unit testing and prototyping only
SqliteSaver Local SQLite Database File Yes (Single server) Persistent across server reboots Single-server apps, internal tools, edge runtimes
PostgresSaver Distributed PostgreSQL Yes (Horizontal cluster) ACID compliant, clustered durability Enterprise production multi-tenant deployments
humanintheloop.py — Interrupt & Escrow State Machine
import os
from typing import TypedDict, Annotated
from langchain_openai import ChatOpenAI
from langchain_core.messages import SystemMessage, HumanMessage
from langgraph.graph import StateGraph, START, END
from langgraph.checkpoint.memory import MemorySaver
from langgraph.types import interrupt, Command

class EscrowState(TypedDict):
    beneficiary: str
    amount: float
    reason: str
    manager_approval: bool
    status: str

llm = ChatOpenAI(model="gpt-4o", temperature=0.0)

def draft_transfer_node(state: EscrowState) -> dict:
    return {"status": "TRANSFER_PENDING_APPROVAL"}

def human_approval_node(state: EscrowState) -> dict:
    # HALTS EXECUTION! Awaits external resume payload
    human_decision = interrupt({
        "question": f"Authorize wire transfer of ${state['amount']} to {state['beneficiary']}?",
        "reason": state["reason"]
    })
    
    approved = human_decision.get("approved", False)
    return {
        "manager_approval": approved,
        "status": "APPROVED_AND_EXECUTED" if approved else "REJECTED_BY_MANAGER"
    }

builder = StateGraph(EscrowState)
builder.add_node("drafter", draft_transfer_node)
builder.add_node("human_gate", human_approval_node)

builder.add_edge(START, "drafter")
builder.add_edge("drafter", "human_gate")
builder.add_edge("human_gate", END)

# Attach Checkpoint Memory
checkpointer = MemorySaver()
escrow_app = builder.compile(checkpointer=checkpointer)

if __name__ == "__main__":
    thread_config = {"configurable": {"thread_id": "tx_session_992"}}
    
    print("--- 1. Initiating Escrow Wire Transfer ---")
    state_snap = escrow_app.invoke({
        "beneficiary": "Acme Cloud Infrastructure Corp",
        "amount": 25000.00,
        "reason": "Annual GPU Cluster Reservation"
    }, config=thread_config)
    
    print("Graph execution paused at interrupt()!")
    print(f"Current State: {state_snap}")
    
    print("\n--- 2. Resuming Execution with Human Approval Command ---")
    resumed_state = escrow_app.invoke(
        Command(resume={"approved": True}),
        config=thread_config
    )
    print("Execution completed!")
    print(f"Final Status: {resumed_state['status']}")
Project 6

Full Production Streamlit Web Application

Backend state graphs must ultimately be exposed to non-technical end users. In Project 6, we embed our LangGraph multi-RAG system into a reactive Streamlit Web Application, incorporating critical production caching patterns.

🎯 Pedagogical Analogy: The Mission Control Flight Deck Cockpit
Rocket engines, thruster solenoids, and navigation computers are complex backend machinery. The astronaut inside the capsule doesn't type raw telemetry code; they look at a streamlined Mission Control flight deck with illuminated status lights, altitude indicators, and responsive levers. Streamlit is that interactive cockpit for your LangGraph engine.
💡 Developer Empathy: The Streamlit Rerun Lifecycle!
Every time a user clicks a button or types in an input box, Streamlit reruns your Python script from line 1 to the end! If you instantiate your vector store or recompile your LangGraph on line 10, your app will reload gigabytes of embeddings and recompile graphs on every single keystroke, causing horrific lag.

Mandatory Fix: Always wrap vectorstore loading and graph compilation in @st.cache_resource so they instantiate once and remain hot in RAM!
app.py — Complete Streamlit Production Web App
import os
import streamlit as st
from typing import TypedDict
from langchain_openai import ChatOpenAI, OpenAIEmbeddings
from langchain_community.vectorstores import Chroma
from langchain_core.messages import SystemMessage, HumanMessage
from langgraph.graph import StateGraph, START, END

st.set_page_config(page_title="AI University Academic & Fees Portal", layout="wide")
st.title("🎓 Multi-PDF University Assistant with LangGraph")

# Step 1: Cached Resource Ingestion
@st.cache_resource
def load_vectorstores():
    embeddings = OpenAIEmbeddings(model="text-embedding-3-small")
    academics = Chroma.from_texts(
        ["Academic Policy: Minimum 85% attendance required. Final exam carries 60% weight."],
        embedding=embeddings, collection_name="acad_st"
    ).as_retriever()
    
    fees = Chroma.from_texts(
        ["Fee Policy: Tuition is $15,000/year. Installment plans available with 2% processing fee."],
        embedding=embeddings, collection_name="fees_st"
    ).as_retriever()
    return academics, fees

acad_retriever, fees_retriever = load_vectorstores()

# Step 2: State
class AppState(TypedDict):
    user_query: str
    target_category: str
    context: str
    response: str

llm = ChatOpenAI(model="gpt-4o", temperature=0.0)

# Step 3: Nodes
def classify(state: AppState) -> dict:
    cat = llm.invoke([
        SystemMessage(content="Classify into: ACADEMICS or FEES."),
        HumanMessage(content=state["user_query"])
    ]).content.strip().upper()
    return {"target_category": cat}

def fetch_acad(state: AppState) -> dict:
    docs = acad_retriever.invoke(state["user_query"])
    return {"context": docs[0].page_content}

def fetch_fees(state: AppState) -> dict:
    docs = fees_retriever.invoke(state["user_query"])
    return {"context": docs[0].page_content}

def synthesize(state: AppState) -> dict:
    ans = llm.invoke([
        SystemMessage(content=f"Context: {state['context']}"),
        HumanMessage(content=state["user_query"])
    ]).content
    return {"response": ans}

# Step 4: Build & Cache Graph
@st.cache_resource
def get_graph():
    b = StateGraph(AppState)
    b.add_node("classify", classify)
    b.add_node("acad", fetch_acad)
    b.add_node("fees", fetch_fees)
    b.add_node("synth", synthesize)
    
    b.add_edge(START, "classify")
    b.add_conditional_edges("classify", lambda s: "acad" if "ACADEMICS" in s["target_category"] else "fees", {
        "acad": "acad", "fees": "fees"
    })
    b.add_edge("acad", "synth")
    b.add_edge("fees", "synth")
    b.add_edge("synth", END)
    return b.compile()

graph = get_graph()

        st.success(f"**Routed Category:** {res['target_category']}")
        st.info(f"**Retrieved Context:** {res['context']}")
        st.markdown(f"### Answer:\n{res['response']}")
